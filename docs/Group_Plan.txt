 Why Dataset B
 •     Better preprocessing story (20 pts). Cholesterol has many zero values and RestingBP has at least
       one. A cholesterol of 0 is impossible, so there is a real data-quality decision to justify. Dataset A's
       missing values are ones you hide yourselves.
 •     SMOTENC is more meaningful. B mixes categorical and numeric features, exactly the case
       SMOTENC exists for.
 •     Clear metric justification. Missing a heart-disease patient (false negative) is costly, so recall-focused
       evaluation argues itself.
 •     SHAP is easy to interpret. Features like ST_Slope, ChestPainType and Oldpeak make clinical sense.
 •     Fast. 918 rows means every CV run takes seconds.
 Downside: B is roughly balanced (about 55% positive), so SMOTE probably will not help much. The assignment
 explicitly says that is a valid finding.

 •     Libraries: pandas, numpy, matplotlib / seaborn, scikit-learn, imbalanced-learn, xgboost, shap, lime

 3. Part 2 - Preprocessing
 •   Split first: train_test_split(..., stratify=y, random_state=SEED). Lock the test set
     away.
 •   Basic pipeline: keep values as-is, SimpleImputer(median) for numeric,
     OneHotEncoder(handle_unknown="ignore") for categorical, inside a ColumnTransformer.
 •   Improved pipeline: replace zeros in Cholesterol and RestingBP with NaN, add missingness indicators
     (add_indicator=True), use KNNImputer or IterativeImputer (scale first for KNN). Justify why 0 means
     "not measured".
 •   Fair comparison: the same Random Forest with basic vs. improved pipeline, 3-fold CV on the training
     set only. This isolates the preprocessing effect.
 •   Talking point: zero-cholesterol rows correlate strongly with heart disease, likely due to how one source
     hospital recorded data. That is a site artifact, not biology.
 •   Deliverable for teammates: a function build_preprocessor(kind="basic" | "improved")
     plus X_train, X_test, y_train, y_test and the cv object.

 Member 2: Modeling (Part 3, Part 4)
 1. Part 3 - Random Forest vs. boosting
 All models use Member 1's improved pipeline and the same cv object.
 •   Random Forest: GridSearchCV over 6 settings, e.g. max_depth in {None, 5, 10} x min_samples_leaf
     in {1, 5}.
 •   XGBoost: 6 settings, e.g. max_depth in {3, 5} x learning_rate in {0.05, 0.1, 0.3}.
 •   AdaBoost: default settings.
 •   Dummy: kept as the reference.
 •   Use return_train_score=True and save train and validation scores for every model (Member 3 needs
     them).
 •   Answer the guiding questions: boosting reduces bias by focusing on hard cases; it overfits with high
     learning rates or deep trees on small or noisy data; did extra complexity actually help?

 2. Part 4 - Imbalance with SMOTENC
 •   Report the class ratio (about 508 positive vs. 410 negative).
 •   Build an imblearn.pipeline.Pipeline in this order: impute and scale numeric features, then
     SMOTENC(categorical_features=[...]) on the un-one-hot-encoded categoricals, then one-hot encode,
     then the model. SMOTENC cannot handle NaNs and should never see one-hot columns; scaling
     matters because SMOTE is distance-based.
 •   Compare the same model with and without SMOTENC in CV. Resampling then happens only inside
     training folds, never on the test set.
